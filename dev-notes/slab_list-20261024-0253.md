# SlabList 设计记录（20261024-0253）

## 背景

旧 `Arena<T>` 基于 `slab` crate，向调用者返回 `Idx<T>`。B+ Tree 的节点通过
`Idx<T>` 再访问 `Arena`，每次比较或取值都需要把 arena 引用一路传下去。

本轮希望换一种分配策略：

- 不再逐元素分配，而是一次分配一个可容纳多个 `T` 的 **Chunk**；
- Chunk 头本身也构建在同一片内存上；
- 多个 Chunk 用 `prev` / `next` 指针组成双向链表；
- 槽位可以乱序归还；
- Arena 直接向调用者返回元素句柄，而不是索引；
- Chunk 内存可以交由配置类型指定的 `Allocator` 分配。

后续已完成接入：`BPlusTree`、节点定义、搜索和比较器全部改用 `SlotPtr`；
`arena_.rs` 与 `slab` 依赖已移除。

## 已确认的决策

### 1. Config 是独立泛型参数，`T` 与 `C` 互不依赖

```rust
pub struct SlabList<T, C = SlabListConfig<DEFAULT_CHUNK_BYTES>>
where
    C: TrConfig,
{
    head_: *mut ChunkHeader,
    tail_: *mut ChunkHeader,
    allocator_: C::Allocator,
    _marker_: PhantomData<(Slot<T>, C)>,
}
```

- `T` 决定槽位中的元素类型；
- `C` 是类型级配置，决定单 Chunk 的 const 字节数和 allocator 类型；
- allocator 实例由 `SlabList` 保存，配置本身不持有 allocator；
- Config 与 Allocator 不再耦合，配置只“指定类型”。

### 2. 类型级 `TrConfig`

```rust
pub trait TrConfig {
    type Allocator: Allocator;
    const CHUNK_SIZE: usize;
}
```

- `Allocator` 只声明类型，实例由 `SlabList` 持有；
- `CHUNK_SIZE` 是 const，避免运行时配置对象；
- `TrConfig` 是内部使用的配置抽象，允许直接使用 const 表达 Chunk 大小。

内置配置是一个类型级 marker：

```rust
pub struct SlabListConfig<const CHUNK_SIZE: usize, A = Global> {
    _marker_: PhantomData<A>,
}

impl<const CHUNK_SIZE: usize, A: Allocator> TrConfig for SlabListConfig<CHUNK_SIZE, A> {
    type Allocator = A;
    const CHUNK_SIZE: usize = CHUNK_SIZE;
}
```

使用方式：

```rust
// 默认配置：64 KiB + Global
let arena = SlabList::<u64>::with_default_config()?;

// 自定义 Chunk 大小，allocator 实例由 SlabList 保存
let arena = SlabList::<u64, SlabListConfig<4096>>::new(Global)?;

// 自定义 allocator 类型，实例通过 new 传入
let arena = SlabList::<u64, SlabListConfig<4096, MyAlloc>>::new(my_alloc)?;
```

`SlabListConfig` 不需要实例化，只作为类型参数使用。

### 3. 布局字段不缓存在 SlabList 中

`SlabList` 不保存 `chunk_bytes`、`chunk_layout`、`slot_offset` 或
`slots_per_chunk` 字段。布局由 `C::CHUNK_SIZE` 在需要时计算：

```text
slot_offset = align_up(size_of::<ChunkHeader>(), align_of::<Slot<T>>())
slots       = (CHUNK_SIZE - slot_offset) / size_of::<Slot<T>>()
```

约束：

- `slots >= 1`，否则返回 `ChunkTooSmall`；
- `slots <= MAX_SLOTS_PER_CHUNK`（2^15），否则返回 `TooManySlots`；
- 布局无法表示时返回 `LayoutOverflow`。

`ChunkLayout` 是公开类型，提供 `ChunkLayout::for_type::<T>(chunk_bytes)` 以及
`layout` / `slot_offset` / `slots_per_chunk` 访问器。`SlabList::new` 在构造时
校验一次，后续计算不可能失败。

Chunk 采用懒分配：`SlabList::new` 只校验配置，不分配内存；第一次 `insert`
才分配第一个 Chunk。

### 4. 不保存使用统计字段

`SlabList` 不保存 `len`、`capacity` 或 `chunk_count` 等使用统计字段，也不提供
对应的查询方法。它只负责管理 Chunk 链表、槽位分配和归还。

### 5. Chunk 内存布局

```text
+----------------------+  <- 分配基址
| ChunkHeader          |
|  prev / next         |
|  free_head: u16      |
|  free_count: u16     |
|  capacity: u16       |
+----------------------+  <- slot_offset
| Slot<T> #0           |
|  value: MaybeUninit  |
|  self_idx: u16       |
|  next_free: u16      |
+----------------------+
| Slot<T> #1           |
| ...                  |
+----------------------+
```

`Slot<T>` 使用 `#[repr(C)]`，`value` 位于槽位起始地址，因此：

- 指向元素的 `*mut T` 同时也是槽位基址；
- 槽位尾部的两个 `u16` 紧跟在 `T` 后面（ZST 时允许偏移为 0）。

### 6. `self_idx` 最高位作 occupied 标记

槽数上限取 `2^15`，而不是 `u16::MAX`，原因是：

- `self_idx` 低 15 位保存槽号；
- `self_idx` 最高位保存 occupied 标记；
- `next_free == u16::MAX` 表示空闲链表结束。

这样 `drop` 可以顺序遍历所有槽位，通过 occupied 位区分“存活元素”和“空闲槽位”，
不需要先遍历空闲链表做标记。

`next_free` 只保存下一个空闲槽号，不参与 occupied 判断。

### 7. `SlotPtr<T>` 只保存 `NonNull<T>`

`SlotPtr<T>` 是一个 `Copy` 的透明句柄，内部只有 `NonNull<T>`，并实现
`Deref` / `DerefMut`。它可以直接存入 B+ Tree 节点，解引用时不再需要 arena 引用。

`remove` 的 O(1) 反向定位过程：

```text
slot_base = ptr as *mut u8
self_idx  = read(slot_base + offset_of!(Slot<T>, self_idx))
idx       = self_idx & 0x7FFF
slot0     = slot_base - idx * size_of::<Slot<T>>()
chunk     = slot0 - slot_offset
```

因此不需要扫描 Chunk 链表。代价是句柄有效性由调用者维护，详见“安全约定”。

### 8. Chunk 链表的近似排序

不按 `free_count` 严格排序，而是：

- 有空闲槽位的 Chunk 尽量在链表头部；
- 某个 Chunk 被写满后移到链表尾部；
- 某个 Chunk 归还槽位后移到链表头部。

因此链表头部始终是可分配的 Chunk（如果还有可分配 Chunk），但它不一定是空闲槽
数量最多的 Chunk。这是“尽量把空闲最多的 Chunk 放在头部”的近似实现，避免了每次
分配/归还都维护严格有序链表的成本。

### 9. 归还与析构

- `remove(ptr) -> T`：先从槽位中 `read` 出 `T`，再清 occupied 位，把槽位压入所属
  Chunk 的空闲链表头部，并把 Chunk 移到链表头部。
- 空闲链表是 LIFO，因此刚释放的槽位会优先被复用。
- `Drop for SlabList` 遍历 Chunk 的所有槽位，只对 occupied 位为 1 的槽位执行
  `drop_in_place`，然后使用 `SlabList` 自己保存的 allocator 释放 Chunk。
- 分配失败时调用 `handle_alloc_error`（通常 abort）。
- 重复 `remove` 会在 occupied 位检查处 panic，避免静默破坏空闲链表。

### 10. ZST 支持

`Slot<T>` 即使 `T` 是 ZST，也包含两个 `u16` 元数据，因此槽位大小至少为 4 字节，
每个槽位仍然有独立地址。

`SlotPtr` 指向槽位基址，而不是 `MaybeUninit<T>::as_mut_ptr()` 可能返回的悬垂地址。
由于 `value` 位于槽位起始地址，ZST 也能通过 `self_idx` 正常反推 Chunk。

### 11. `Idx` -> `SlotPtr` 接入

- `node_` 中：
  - `TreeNodePtr<M, K, V> = SlotPtr<TreeNode<M, K, V>>`；
  - `DataPtrOrdArr = OrderedArray<M, SlotPtr<(K, V)>, ()>`；
  - `IndexPtrOrdArr = OrderedArray<M, SlotPtr<(K, V)>, TreeNodePtr<M, K, V>>`。
- 比较器：
  - `HomoSlotComparer` / `HeteroSlotComparer` 直接解引用 `SlotPtr`，不再持有
    arena 引用；
  - `TrPickKeyPolicy`、`IndexKeyComparer`、`IndexOrdKeyComparer` 不再需要
    `&Arena` 参数。
- `search_` 的递归搜索函数不再接收 node arena，直接从 `TreeNodePtr` 解引用节点。
- `BPlusTree`：
  - `data_arena_` / `node_arena_` 改为 `SlabList<(K, V)>` 与
    `SlabList<TreeNode<M, K, V>>`；
  - 由于 `SlabList::new` 会校验默认 Chunk 是否能容纳至少一个元素，
    `BPlusTree::new_in` 改为返回 `Result<Self, SlabListError>`，不再是一个
    `const fn`；
  - 未显式指定配置时使用默认 `SlabListConfig<DEFAULT_CHUNK_BYTES>` 与
    `Global` allocator。
- `arena_.rs` 已删除，`slab` 依赖已从 `Cargo.toml` 移除；`x_deps` 不再导出
  `slab`。

## 公开 API

```rust
pub const DEFAULT_CHUNK_BYTES: usize = 64 * 1024;
pub const MAX_SLOTS_PER_CHUNK: usize = 1 << 15;

pub trait TrConfig {
    type Allocator: Allocator;
    const CHUNK_SIZE: usize;
}

pub struct SlabListConfig<const CHUNK_SIZE: usize, A = Global> { /* marker */ }
impl<const CHUNK_SIZE: usize, A: Allocator> TrConfig for SlabListConfig<CHUNK_SIZE, A> { /* ... */ }

pub struct SlabList<T, C = SlabListConfig<DEFAULT_CHUNK_BYTES>>
where
    C: TrConfig,
{ /* head, tail, allocator, marker */ }

impl<T, C> SlabList<T, C>
where
    C: TrConfig,
{
    pub fn new(allocator: C::Allocator) -> Result<Self, SlabListError>;
    pub const fn allocator(&self) -> &C::Allocator;
    pub const fn chunk_bytes(&self) -> usize;
    pub fn slots_per_chunk(&self) -> usize;
    pub fn insert(&mut self, value: T) -> SlotPtr<T>;
    pub fn remove(&mut self, ptr: SlotPtr<T>) -> T;
}

impl<T> SlabList<T, SlabListConfig<DEFAULT_CHUNK_BYTES>> {
    pub fn with_default_config() -> Result<Self, SlabListError>;
}

pub struct ChunkLayout { /* layout, slot_offset, slots_per_chunk */ }
impl ChunkLayout {
    pub fn for_type<T>(chunk_bytes: usize) -> Result<Self, SlabListError>;
    pub const fn layout(&self) -> Layout;
    pub const fn slot_offset(&self) -> usize;
    pub const fn slots_per_chunk(&self) -> usize;
}

pub struct SlotPtr<T> { /* NonNull<T> */ }
impl<T> Deref for SlotPtr<T> { type Target = T; }
impl<T> DerefMut for SlotPtr<T> { /* ... */ }
```

## 安全约定

`SlotPtr` 是无生命周期的 `Copy` 裸指针句柄，类型系统无法约束它的有效期。调用方必须：

- 只使用由仍然存活的同一 arena 的 `insert` 返回的句柄；
- 不在槽位已经 `remove` 后继续解引用（除非它被重新插入）；
- 不同时通过多个句柄创建别名 `&mut T`；
- 不在 `SlabList` drop 后继续使用句柄。

`remove` 会对 occupied 位做检查，因此同一槽位的重复归还会 panic；但把其他 arena
的句柄或悬垂句柄传给 `remove` 属于逻辑错误，可能触发未定义行为。这是为了换取
O(1) 反向定位、避免 Chunk 链表扫描而接受的取舍。

## 测试覆盖

`src/slab_list_/list_.rs` 中包含以下中英双语单元测试：

- 过小和槽数超限的 const 配置被拒绝；
- 基本插入、`Deref` / `DerefMut`、乱序归还；
- 空闲链表 LIFO 复用；
- Chunk 扩容、写满移尾、从中间/尾部释放后移回头部并复用；
- `drop` 只析构存活元素，不重复析构空闲槽位；
- ZST 槽位地址互异且可归还；
- 重复 `remove` panic；
- 默认配置；
- 自定义 `TrConfig` 实现；
- 外部 allocator 的分配/释放次数。

以上 11 个单元测试已通过 `cargo test slab_list_`、`cargo test`（含文档测试）
与 `cargo miri test slab_list_`；`cargo clippy --all-targets` 对新模块无告警。

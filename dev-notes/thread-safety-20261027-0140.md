# 树的 Send / Sync marker（20261027-0140）

## 背景

下游报告 `BTree` / `BPlusTree` 不能跨线程移动。原因是树内部的
`SlotPtr<T>` 基于 `NonNull<T>`，而 arena 中的 Chunk 链表保存 `*mut ChunkHeader`；
`NonNull` 与裸指针默认都不是 `Send` / `Sync`，所以树无法自动获得 marker。

## 技术决策

### 1. 直接在树类型上声明 marker

没有给 `SlotPtr<T>` 实现 `Send` / `Sync`。`SlotPtr` 是 `Copy` 的裸句柄，若在
所有使用场景下都声明 `Sync`，内部代码可以通过复制句柄绕过借用规则，风险较高。
本轮只在公开的树与迭代器类型上做 unsafe marker，并给出明确边界：

```text
Send: K: Send, V: Send, C: Send, Cfg: Send, Cfg::Allocator: Send
Sync: K: Sync, V: Sync, C: Sync, Cfg: Sync, Cfg::Allocator: Sync
```

这与 `BTreeMap` 对 `K`、`V`、allocator 的要求一致；Comparer 与 `Cfg` 是本 crate
新增的配置状态，因此也纳入约束。

### 2. 安全性论证

`Send`：

- 树拥有全部 `(K, V)` 与 Chunk 内存；移动树后原线程不再持有树的所有权；
- 裸指针只指向树自己拥有的 Chunk，Chunk 地址在移动中不变；
- Comparer 与 allocator 随树一起移动，要求二者 `Send`；
- `SlabList` 的 `PhantomData<Cfg>` 不保存运行时值，但仍要求 `Cfg: Send`。

`Sync`：

- `&BPlusTree` / `&BTree` 只开放只读查询与不可变迭代；
- 插入、删除、`get_mut`、`iter_mut`、`range_mut` 都需要 `&mut self`，不能与
  共享引用并存；
- 要求 `K`/`V`/Comparer/`Cfg`/allocator 都 `Sync`，没有未同步的内部可变状态；
- Chunk 链表只会在 `&mut self` 的分配/删除/`clear` 路径中修改。

### 3. 迭代器 marker

公开迭代器内部也保存节点句柄，因此补了同样的条件：

- 不可变迭代器（`TreeIter`、`RangeIter`、`Keys`、`Values`）：
  `Send` / `Sync` 要求 `K`/`V: Sync`；
- 可变迭代器（`IterMut`、`RangeIterMut`、`ValuesMut`）：
  `Send` 要求 `K`/`V: Send`，`Sync` 要求 `K`/`V: Sync`；
- 可变迭代器的 `&self` 只能读 `size_hint`，前进需要 `&mut self`，所以共享
  `&IterMut` 不会产生对 value 的可变访问。

`Keys` / `Values` / `ValuesMut` 是包装类型，内部 marker 已满足后自动获得相应
auto trait。

## 测试

新增 `tests/thread_safety.rs`：

- 编译期断言树、范围/可变/不可变迭代器及 key/value 视图的 `Send` / `Sync`；
- `thread::scope` 中多线程共享 `&tree` 查询与迭代；
- `thread::spawn` 中移动整棵树；
- 跨线程移动 `iter()` 与 `iter_mut()` 并完成迭代/修改；
- 自定义 `CHUNK_SIZE_4K` 配置的树同样满足 marker。

Miri（strict provenance，含线程）通过全部 `tests/thread_safety.rs` 测试。

# 父指针恢复与无额外堆分配记录（20261024-2233）

## 背景

此前 B+ Tree 为了避免 root 的 dummy parent，删除了节点中的父指针，改用独立的
`PathFrame` SlabList 路径栈。B Tree 的迭代器则使用 `Vec` 保存从 root 到当前节点
的工作栈。

这两处都带来了不必要的复杂度：

- B+ Tree 的插入/删除需要额外维护 path 栈，路径帧的压入/归还分散在多个函数里；
- B Tree 迭代器虽然工作栈容量只有 `O(log n)`，但仍然在每次 `iter()` 时做一次
  非 SlabList 的堆分配；
- 两种树的“向上”操作没有统一依赖节点自身结构。

结论是恢复节点内的父指针，并严格限制两棵树的堆分配来源。

## 技术决策

### 1. 两种树的节点都保存父指针

```rust
// bplus_tree/node_.rs
struct NodeBase<const M: usize, K, V> {
    parent_: Option<TreeNodePtr<M, K, V>>,
}

struct IndexNode<...> { base_: NodeBase<...>, children_: ... }
struct DataLeaf<...> { base_: NodeBase<...>, order_arr_: ..., prev_, next_ }

// btree/node_.rs
struct Node<const M: usize, K, V> {
    parent_: Option<TreeNodePtr<M, K, V>>,
    first_child_: ...,
    entries_: ...,
}
```

根节点的 `parent_` 为 `None`，不使用 dummy 节点。父指针与普通孩子指针一样是
`SlotPtr`，不拥有节点，不参与 Drop，因此父子互指不会产生所有权问题。

没有额外保存 `parent_idx_`：需要孩子下标时，扫描父节点中很小的孩子数组即可。
这样可以避免在每次插入/删除/借位/合并时批量修正兄弟下标；树节点数组的容量 `M`
很小，扫描成本可忽略。

### 2. B+ Tree 删除 path 栈

- 删除 `bplus_tree/path_.rs`；
- `BPlusTree` 删除 `path_` 与 `path_arena_` 字段；
- `descend_to_leaf_` 删除，统一使用只读的 `find_leaf_`；
- 插入/删除后沿 `parent_` 向上更新 separator；
- 借位/合并时同步维护被移动孩子的父指针；
- root 分裂/收缩时更新新 root 的父指针。

插入的向上传播仍然采用“pending 项 + 父指针”的循环；删除的借位/合并逻辑保留
原有分支，只把 `cursor`/`prev` 替换为 `node_parent_` 与 `child_index_`。

### 3. B Tree 迭代器改为父指针中序后继

```text
当前项在内部节点：后继 = 右子树最小项
当前项在叶子且还有下一项：同叶子的下一项
当前项是叶子最后一项：
    沿父链向上，找到第一个“当前孩子不是最后一个孩子”的祖先
    取该祖先中对应的项；若一直到最后孩子则结束
```

迭代器只保存 `current_: Option<(节点, 下标)>` 和 `remaining_`，没有 `Vec`、
没有工作栈、没有 `tree_height_`。删除 `btree/search_.rs` 中只为 `Vec` 预留容量
服务的 `tree_height_`。

### 4. 堆分配约束

两棵树的实现代码（非测试代码）只允许通过 `SlabList` 进行堆分配：

- B+ Tree：`SlabList<(K, V)>` 数据 + `SlabList<TreeNode>` 节点；
- B Tree：`SlabList<Node>`；
- 不使用 `Vec`、`Box`、`String` 等作为节点或遍历状态；
- 测试代码中的 `Vec`、`BTreeMap`、`String` 只用于构造测试数据和模型对拍，
  不属于树的实现。

`cargo grep` 检查结果：`src/bplus_tree`、`src/btree`、`src/node_` 的非测试代码
中，`Vec` 只出现在 `#[cfg(test)]` 的 B+ Tree 不变量检查代码和文档示例中。

### 5. 恢复公开 re-export

`btree` 重命名提交同时删除了 `OrderedArray` / `SlabList` 等根级
`pub use`，导致 11 个文档测试无法编译。节点重构不涉及这些公开 API 的删除，
因此恢复：

```rust
pub use ordered_arr_::{...};
pub use slab_list_::{...};
```

同时把 crate 文档中的旧模块路径更新为 `btree`。

## 影响

- B+ Tree 的插入/删除不再分配 path SlabList；父指针成为唯一的向上导航结构；
- B Tree 的 `iter()` 完全零堆分配，迭代器体积缩为两个 `usize`/指针字段；
- 两种树的节点都保存父指针，结构操作必须维护；
- 父指针加入不变量检查：root 的 parent 为 `None`，每个孩子的 parent 指向当前节点；
- 公开 API 不变（除恢复此前误删的 re-export）。

## 后续

- 如果未来需要 O(1) 的孩子下标，可以再引入 `parent_idx_`，但需要在分裂/合并时
  批量维护；当前扫描孩子数组已经足够。
- B+ Tree 的父指针目前主要用于插入/删除向上传播；后续如需统一两种树的迭代方式，
  也可以在 B+ Tree 上使用父指针迭代，但叶子链已经足够高效。

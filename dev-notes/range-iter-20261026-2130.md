# 范围查询与可变迭代 API（20261026-2130）

## 背景

两棵树此前只提供正向 `iter()`，与 `BTreeMap` 相比缺少：

- `range` / `range_mut` 及异构 Comparer 版本；
- `iter_mut`、`keys`、`values`、`values_mut`；
- `contains_key`、`first_key_value`、`last_key_value`、`clear`。

用户要求在不增加临时堆分配的前提下补齐这些能力。现有 B+ Tree 沿叶子链迭代、
B Tree 沿父指针计算中序后继，两者本来就不需要工作栈，因此范围 API 继续沿用
这两个游标模型。

## 技术决策

### 1. 范围首尾在构造时一次定位

如果迭代器保存上界并逐项比较，就需要在迭代器类型中携带边界类型 `Q` 与
Comparer 泛型；更关键的是，`range` 的边界参数是按值传入的，`RangeBounds`
返回的边界引用只在函数体内有效，不能直接存入迭代器。

因此 `range_positions_` 在构造时完成两次 `O(log n)` 搜索：

1. 首位置：第一个满足下界的项；
2. 尾位置：最后一个满足上界的项。

迭代器只保存 `(节点, 下标)` 形式的首、尾游标：

- 不可变迭代器同时保存首尾，支持 `DoubleEndedIterator`；
- 可变迭代器保存首位置与尾哨兵，只向前移动；
- 首尾游标相等时，下一次产出即消耗最后一项。

空区间（包括 `start > end`）在构造时被判定为 `None`，迭代器为空。这样既不需要
在迭代器里保存边界，也不需要在每个元素上重复比较边界。

### 2. B+ Tree：叶子链游标

B+ Tree 的数据都在叶子里，叶子有 `prev` / `next` 链。首尾定位复用现有
`find_leaf_` 与叶子内 `lower_bound_by` / `upper_bound_by`：

- 下界 `Included` / `Excluded` 分别取第一个 `>=` / `>` 的位置；
- 上界 `Included` / `Excluded` 分别取最后一个 `<=` / `<` 的位置；
- 位置越过叶子末尾时跳到 `next` 叶子，倒退时跳到 `prev` 叶子。

可变迭代通过 `SlotPtr<(K, V)>` 直接取得 `&mut V`。数据 arena 与节点 arena
彼此独立，因此节点元数据可以继续以共享引用读取。

### 3. B Tree：父指针游标与字段级可变访问

B Tree 的数据嵌在节点数组中。`iter_mut` / `range_mut` 必须允许调用者同时持有
同一节点内多个 `&mut V`（例如用 `collect::<Vec<_>>()` 收集），所以不能在每次
`next()` 时重新创建覆盖整个 `Node` 的 `&mut Node`，否则会与先前交出的 `&mut V`
形成别名。

实现方式：

- 在 `OrderedArray` 中新增 `len_raw_`、`elem_raw_at_`、`elem_raw_mut_at_`，
  通过 `ptr::addr_of!` / `addr_of_mut!` 读取计数字段、`order_` 映射和元素指针；
- 在 `btree::node_` 中新增节点元数据与子节点的裸指针读取函数；
- `entry_mut_raw_` 只对目标元素的 `key` 与 `node_value.value_` 两个字段做
  字段级投影，不创建覆盖整个节点或整个数组的引用；
- 迭代器在交出当前项之前先计算后继，避免在 `&mut V` 存活期间重新访问结构。

不可变范围迭代器仍使用普通引用路径，并新增 `prev_entry_` 支持 `.rev()`。

### 4. 零临时分配

新增 API 的迭代器状态只有：

- `Option<(TreeNodePtr, usize)>` 游标；
- `usize` 剩余数量（仅 `IterMut`）；
- `PhantomData`。

没有 `Vec`、`Box`、临时数组或工作栈。`tests/allocator.rs` 使用不实现 `Clone`
的 `CountingAlloc`，在插入完成后记录分配次数，执行全部新增迭代 API 并确认
分配次数不变。

## 公开 API

两棵树对称新增：

```text
iter_mut
keys / values / values_mut
range / range_mut
range_with_comparer / range_mut_with_comparer
contains_key / first_key_value / last_key_value / clear
```

新增公开迭代类型：

```text
BPlusTree: IterMut, RangeIter, RangeIterMut, Keys, Values, ValuesMut
BTree:     BTreeIterMut, BTreeRangeIter, BTreeRangeIterMut,
           BTreeKeys, BTreeValues, BTreeValuesMut
```

`&mut Tree` 也实现了 `IntoIterator`，迭代项为 `(&K, &mut V)`。

## 语义

- 范围方向完全由 Comparer 决定；反向 Comparer 下 `range(20..10)` 是有效区间；
- 普通 Comparer 下起点晚于终点时返回空迭代器，而不是 panic；
- 不可变 `RangeIter` 支持 `DoubleEndedIterator`；
- `RangeIterMut` / `IterMut` 只能修改 value，key 与树结构保持不变。

## 验证

- 新增集成测试覆盖边界、空区间、反向 Comparer、异构 Comparer、随机范围与
  `BTreeMap` 对拍、可变迭代与大量同时存活的 `&mut V`；
- `tests/allocator.rs` 验证迭代 API 不增加分配；
- `cargo test`、`cargo clippy --all-targets -- -D warnings`、
  `RUSTDOCFLAGS='-D warnings' cargo doc --no-deps` 通过；
- Miri（strict provenance）通过 B Tree 大量 `&mut V` 与字段级裸指针访问测试。

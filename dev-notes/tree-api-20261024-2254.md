# 树级错误、节点模块撤销与 btree 命名（20261024-2254）

## 背景

上一轮暴露了两个问题：

1. `BPlusTree::new_in` / `from_iter_by` 与 `BTree::new_in` / `from_iter_by`
   的公开签名返回 `SlabListError`，但 `SlabListError` 属于 crate 内部；
   恢复根部 `pub use slab_list_` 会再次扩大公开 API，因此需要树级错误类型。
2. 之前提取的 `node_` 模块中并没有两棵树共用的节点类型：`NodePtr` 只是
   `SlotPtr` 的别名，`node_ref_` / `node_mut_` 只是两个薄函数，B+ Tree 的
   `TreeNode` 与 B Tree 的 `Node` 完全独立。按“有共用才提取”的原则，这个
   模块不应保留。

同时，模块与文件命名统一为 `btree`。

## 技术决策

### 1. 公开 TreeError

新增 crate 根级公开类型：

```rust
pub struct TreeError {
    inner_: SlabListError,
}
```

- `SlabListError` 仍然是 crate 内部类型；
- `TreeError` 只暴露 `Debug` / `Display` / `Error`，包装关系不进入公开签名；
- `new_in` / `from_iter_by` 返回 `Result<Self, TreeError>`；
- 构造时用 `TreeError::from_slab_` 转换内部错误。

这是本轮唯一新增的公开 API，已得到确认。

### 2. 撤销 node_ 模块

`node_` 中的内容：

```text
node_/ptr_.rs          NodePtr = SlotPtr 别名 + 两个访问函数
node_/bplus_tree_.rs   B+ Tree 节点（仅 B+ Tree 使用）
node_/btree_.rs        B Tree 节点（仅 B Tree 使用）
```

没有共享节点类型，因此撤销：

```text
src/bplus_tree/node_.rs   B+ Tree 的 TreeNode / IndexNode / DataLeaf
src/btree/node_.rs        B Tree 的 Node / NodeValue
```

每个节点文件自行定义：

- `TreeNodePtr<...> = SlotPtr<...>`；
- `node_ref_` / `node_mut_`；
- 父指针与节点辅助函数。

两棵树真正共享的仍然是 `Comparer`、`SlabList`、`SlotPtr` 与 `OrderedArray`，
它们已经位于 crate 根层。

### 3. btree 命名统一

- 测试文件重命名为 `tests/btree.rs`；
- 开发日志文件重命名为 `dev-notes/btree-20261024-2155.md`；
- 所有模块路径、文档、日志统一使用 `btree`；
- B Tree 节点模块统一使用 `btree::node_`。

## 公开 API

当前 crate 根公开导出：

```text
BPlusTree, ConflictInfo, TreeIter
BTree, BTreeConflictInfo, BTreeIter
OrdComparer, TrComparer
TreeError
```

`SlabList`、`SlabListConfig`、`SlotPtr`、`ChunkLayout`、`TrConfig`、
`OrderedArray` 等保持内部，不通过 crate 根导出。

> 后续变更（20261024-2330）：树增加了最后一个泛型参数 `A = Global`，构造器改为
> `new` / `new_in(allocator)` / `with_comparer` / `with_comparer_in`，`_by` 方法
> 改名为 `_with_comparer`。详见 `tree-allocator-20261024-2330.md`。

# 节点层提取尝试与撤销（20261024-2208）

## 初始尝试

B 树加入后，曾尝试把两棵树的节点定义集中到 crate 根级 `node_/`：

```text
src/node_/
├── bplus_tree_.rs   B+ Tree 的 TreeNode / IndexNode / DataLeaf
├── btree_.rs       B Tree 的 Node / NodeValue
└── ptr_.rs          通用 NodePtr / node_ref_ / node_mut_
```

当时的理由是：两种树的节点都在 `SlabList` 中，且都需要通过 `SlotPtr` 取得
节点引用。

## 复核结论

这个提取不成立：

- `NodePtr<N>` 只是 `SlotPtr<N>` 的别名，本身不是新的节点抽象；
- `node_ref_` / `node_mut_` 只是两个与具体节点类型无关的薄函数；
- B+ Tree 的 `TreeNode` / `IndexNode` / `DataLeaf` 与 B Tree 的 `Node` 布局、
  不变量和使用方式完全不同，没有任何共享的节点类型。

按照“有共用才提取”的原则，`node_` 模块没有保留价值，已撤销。

## 当前结构

```text
src/bplus_tree/node_.rs   B+ Tree 的 TreeNode / IndexNode / DataLeaf
src/btree/node_.rs        B Tree 的 Node / NodeValue
```

每个节点文件自己定义：

- `TreeNodePtr<...> = SlotPtr<...>`；
- `node_ref_` / `node_mut_` 两个访问函数；
- 该树专有的节点操作与父指针辅助函数。

两棵树仍然共享 `Comparer`、`SlabList`、`SlotPtr` 和 `OrderedArray`，但这些
共享项位于 crate 根层，不需要再包一层 `node_`。

## 影响

- 节点布局与树算法重新放在同一个树模块中，阅读时不需要跨目录跳转；
- 不再存在“这里看起来像共享节点层，但其实只有一棵树使用”的误解；
- 公开 API 不变；
- `btree/node_.rs` 的 B Tree 节点直接使用 `SlotPtr<Node>`，不再依赖任何
  跨树模块的节点别名。
